# Branding assets

Source files for the app icon. Tracked in git so the brand identity persists
outside the gitignored `build/` directory. Platform icons (`.icns`, `.ico`,
`Assets.car`) are NOT stored here -- they are regenerated by wails at build time.

## Files

- `icon.svg` - icon vector source (1024x1024 viewBox).
- `appicon.png` - 1024x1024 raster, rendered from `icon.svg`. Wails uses this
  as input to `wails3 generate icons`.
- `lockup.svg` - horizontal icon + wordmark lockup (1600x400 viewBox).
  Embedded directly in the project README -- GitHub renders SVG natively, and
  the wordmark uses `system-ui` so the host's system font (SF Pro on macOS,
  Segoe UI on Windows) renders the type. Avoids font-fallback issues that
  rasterising via `rsvg-convert` would introduce.

## Build integration

`build/Taskfile.yml` -> `generate:icons` copies `appicon.png` into `build/` and
runs `wails3 generate icons` to produce the platform-specific bundles
(`darwin/icons.icns`, `windows/icon.ico`, `darwin/Assets.car`).

## Regenerating `appicon.png` from `icon.svg`

After editing `icon.svg`:

```bash
rsvg-convert -w 1024 -h 1024 assets/branding/icon.svg -o assets/branding/appicon.png
```

Then build the app -- wails will pick up the new `appicon.png` and regenerate
the platform icons automatically.

`lockup.svg` is consumed directly (no PNG export step) so editing it just
updates the README rendering.

Requires `librsvg` (`brew install librsvg`).
